Codesign Gym

A Gymnasium-like package for co-design problems — the doubly non-stationary setting where an agent’s embodiment is optimized alongside its control policy.

Co-design is two coupled optimization loops. A slow outer loop searches over the embodiment θ; a fast inner loop learns the control policy π. Neither can be evaluated without the other — the environment is non-stationary in both.

Abstract

Optimize the body and the brain, together

Most reinforcement-learning benchmarks fix the agent’s body and ask only for a controller. But in robotics, energy systems, wireless infrastructure, and beyond, the design of the agent is itself a decision — and the best design depends on the policy that will run on it, while the best policy depends on the design. This is co-design: a doubly non-stationary optimization problem.

Codesign Gym is a minimal, backward-compatible extension of the Gymnasium API that exposes the embodiment as a first-class, optimizer-agnostic object alongside the usual control interface. It ships nine environments spanning video games, dexterous manipulation, legged locomotion, electricity grids, wireless networks, scaled racing, and warehouse logistics — each with several difficulty presets, native vectorization, and a documented per-episode return window. Control stays pure Gymnasium, so existing RL and control stacks plug in unchanged; design search is left entirely to the user’s optimizer.

The Problem

What makes co-design hard

Embodiment θ

A dict of editable design parameters — fingertip meshes, a Pokémon team, shelf placements, solar & battery sizing — each with declared bounds, driven by any optimizer.

Control policy π

Standard Gymnasium interaction — steering, dispatch, joint torques, battle moves. Reuse existing RL and control methods without reinventing the wheel.

The coupling

Storage is worthless to a myopic policy and valuable to an anticipatory one; grip a cautious driver never uses is grip paid for in mass. Design and policy quality cannot be judged apart.

The API

A tiny, backward-compatible extension

The embodiment threads through the same three calls you already know. Everything else is unchanged Gymnasium. 

import codesign_gym as cg

# one entry point returns (env, base_embodiment)
env, theta0 = cg.make_vec("NeroGraspTiny", num_envs=8)

# an outer optimizer proposes a design ...
theta = my_design_optimizer.propose(theta0)
obs, rejected, info = env.reset(embodiment=theta)

# ... an inner policy acts against it
for t in range(horizon):
    action = policy(obs)
    obs, reward, term, trunc, info = env.step(action)

One entry point. make_vec(env_id, num_envs, …) and make(…) are the only public constructors; both return (env, base_embodiment).

Structural validation only. validate_embodiment rejects impossible designs (out of bounds, wrong shape, duplicate cells) — never merely bad ones. Finding good designs is the optimizer’s job.

Evaluation is safe. With is_eval_env=True, a design passed to step is silently dropped, so a fixed embodiment cannot be reshaped mid-episode.

Under the Hood

Lazy registry, native vectorization

Heavy dependencies never import until their environment id is requested, and every environment vectorizes in whatever way is native to it.

Vectorization is native, not wrapped: JAX vmap for Jumanji and F1TENTH, process shards for Showdown, MuJoCo Warp for the manipulation tasks. Adding an environment is one build_vec function and one registry row.

The Suite

Nine environments, six domains

Each is tagged with its embodiment, its control policy, and a per-episode return window [max / min].

Pokémon Showdown
pokenv · poke-env
A turn-based battle simulator. Design a team and learn a strategy to beat a chosen opponent or a League gauntlet.
design: team composition  ·  policy: battle moves
Video game Random / MaxPower / Heuristic +28 / −28
Solar Panel Cleaner
panel_cleaner · MuJoCo Warp
A quadruped carrying a roller arm walks up to tilted panels and sweeps them cell-by-cell. Every leg and arm link deforms independently.
design: leg & arm morphology  ·  policy: walk & sweep
Loco + Manip Reach / Stability / Traverse +10 / 0
Grasping Small Objects
nerograsp · MuJoCo Warp
A LEAP hand grasps small and thin objects — fasteners, tools, a washer — from a flat surface. Full-mesh fingertip designs.
design: fingertip meshes  ·  policy: grasp strategy
Manipulation Tiny / Small / Thin / All ≈+13 / 0
Catcher Robot
ball_catcher · MuJoCo Warp
A robot catches thrown objects across a spread of trajectories — from close low pitches to distant lofted throws.
design: arm & hand geometry  ·  policy: catch control
Loco + Manip Pitch / Arc / Fielding +10 / 0
LQ Structure
lq_structure · control + cvxpy
A mass-spring-damper chain: design masses, stiffness, damping and actuator/sensor placement; regulate against disturbances. Exact per-design ground truth.
design: plant + sensor/actuator  ·  policy: LQR / LQG / QP
Control ground-truth sanity check 0 / −∞
Microgrid Sizing & Dispatch
microgrid · python-microgrid
Size solar, battery and generator; dispatch charge, discharge, curtailment and import against stochastic demand and irradiance — the two-stage problem, done jointly.
design: capacity sizing  ·  policy: dispatch
Energy Random / Forecast / Campus / Off-grid +720 / −270k
Wireless Network Placement
mobile_env · mobile-env
Choose how many base stations to deploy, where, and at what power; manage which cell each moving user connects to. A variable-size design that reshapes the spaces.
design: base-station deployment  ·  policy: cell selection
Infrastructure Dense urban / Suburban / Rural +100 / −100
Vehicle Setup (F1TENTH)
f1tenth · f1tenth_gym_jax
A scaled racing car in a time trial: tune tyre grip, cornering stiffness, drive power and weight distribution — mass is derived from the upgrades. The cleanest transition-level design testbed.
design: vehicle setup  ·  policy: steering + throttle
Racing · JAX Spielberg / Levine ±1 lap
Warehouse Layout
robot_warehouse · Jumanji
Place shelves on a fixed floor; a fleet of robots retrieves requested shelves to goals. Aisles are emergent — corridors appear wherever shelves are not.
design: shelf placement  ·  policy: joint navigation
Layout · JAX Small / Medium / Congested +1000 / 0

Get Started

Install & run

Python 3.11+. The base install includes the lightweight and MuJoCo/JAX environments; two extras pull the git-only Pokémon and F1TENTH stacks.

pip install codesign-gym               # base suite

# GPU-backed JAX environments (e.g. Racing)
pip install -e . && codesign-gym-install-jax-gpu

# Pokemon Showdown (needs Node.js >= 22)
pip install 'codesign-gym[showdown]'
codesign-gym-install-showdown

python -c 'import codesign_gym as cg; print(cg.list_envs())'
